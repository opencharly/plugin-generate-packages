# 2026.242.0614 — fix: scope the discover walk so it skips the Go test fixture

## Summary

Repairs a regression I introduced: the `candy` workflow is failing on `main` here.

The root `charly.yml` I added (opencharly/plugin-generate-packages#8) used
`recursive: true`, which descends into `candy/generate-packages/testdata/charly.yml` — a
**Go test fixture**, not a deployable candy. `validate` rightly rejected it:

```
candy "testdata": must have at least one install file (candy manifest distro: packages,
  root.yml, pixi.toml, pyproject.toml, environment.yml, package.json, Cargo.toml, or user.yml),
  a candy: field, an external_builder:, or a plugin: block
candy "testdata": missing required `plan:` list (ADE is mandatory; the spec IS the test)
```

`recursive: false` matches the plugin repo layout exactly — `candy/<name>/charly.yml` is
found, nested fixtures are not. This is the only repo of the 94 in the sweep with a nested
`charly.yml`, which is why it is the only one that broke.

## How tested

Against a binary built from **this repo's own pinned charly tag** (`v2026.238.1242`).

**The real candy is still discovered, and validate passes:**

```
$ charly box validate
exit=0
$ charly box list candies
generate-packages [testing]
```

(the `testdata` fixture is correctly absent)

**The gate still bites** — a non-recursive walk that found nothing would be worthless.
Changing this repo's own `- command:generate-packages` provider entry to `- notaclass:`:

```
charly: error: command "validate": 2 validation errors:

  candy "generate-packages": CUE schema: .../candy/generate-packages/charly.yml:
  candy "generate-packages": 2 errors in empty disjunction:
```

So the repo keeps the working gate the earlier PR was for, and its `candy` workflow goes
green again.
