# 2026.256.1235 — chore(deps): bump the sdk to v0.2026256.1220 (shared-host packaging)

## Summary

Bump `github.com/opencharly/sdk` → `v0.2026256.1220` to adopt the packagekit **shared-host
packaging hard cutover** (opencharly/sdk#258), and migrate the e2e fixture to the layout that
cutover requires: one `charly-lib` host + `plugin-<word>` **symlinks** to it, instead of per-plugin
binaries.

**Accounting for every diff item:**

- `github.com/opencharly/sdk` `v0.2026250.948` → `v0.2026256.1220` — the change this PR adopts.
- `github.com/opencharly/spec` `v0.2026250.929` → `v0.2026254.503` — **required by the sdk bump**:
  sdk `v0.2026256.1220`'s `go.mod` requires `spec v0.2026254.503`, so MVS moves the plugin's spec
  pin to it. No plugin code depends on a new spec API; `go mod tidy` is the sole reason.
- `candy/generate-packages/e2e_test.go` — the fixture + assertions move to the shared-host layout.

Releasing this plugin is what makes the shared-host packaging available to the distro repos
(`charly-arch#5` and the sibling distro batches).

`TestGeneratePackagesE2E` drives the full plugin path (`runFromArgs → Kong → runGeneratePackages →
sdk/packagekit.Build`) and builds a real package for every requested format (deb/rpm/archlinux/apk/
ipk) and both variants, asserting the emitted `.PKGINFO` + tar file list include `usr/bin/charly`,
the single `…/plugins/charly-lib`, BOTH `plugin-<word>` symlinks (with link target `charly-lib`,
read from the tar `Linkname`), and BOTH `.providers` manifests.

### Change class / bed

This is a **dependency bump + test-fixture migration** (no production source change). The plugin's
runtime artifact is rebuilt by this repo's own `release.yml` on tag; the end-to-end packaging bed
that consumes the shipped plugin is the distro migration batch **opencharly/charly-arch#5** (and the
sibling `charly-{fedora,debian,ubuntu,alpine,openwrt}` batches). The repo's CI `test` + `build`
checks (green) are the in-repo gate for this class.
