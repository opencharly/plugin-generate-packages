# 2026.226.0001

Initial release of the `charly generate-packages` command plugin — the nFPM
packaging engine for the OpenCharly project, replacing the `pkg/` submodule
packaging workflow (`charly box pkg` + the PKGBUILD/spec/debian-control
machinery).

- **Command surface only**: the Kong grammar + provider wiring; every
  nFPM/parsing/variant/optdepends function lives in `sdk/packagekit` (the shared
  nFPM packaging driver).
- **`--candy` is the single metadata input**: the plugin reads the `packaging:`
  section from a charly candy's charly.yml and builds the packages from that +
  the flags. No deps table, no other metadata resource.
- **Per-variant plugin sets**: `--variant` selects the variant from
  `packaging.variants`; the package name is `charly` for the format's
  `default_variant`, `charly-<variant>` otherwise; the `--plugins` dir is
  filtered to the variant's plugin list.
- **All six nFPM formats**: deb, rpm, apk, archlinux, ipk, msix. The charly
  release publishes the five Linux formats; msix is plugin-supported +
  CI-exercised but deferred (charly has no Windows binary).
- **Archlinux optdepends injection**: `sdk/packagekit` post-processes the
  `.pkg.tar.zst` to inject `optdepend = <pkg>: <desc>` lines into `.PKGINFO`
  (nFPM does not emit them).
- **Dual placement**: compiled-in in-proc (`Invoke(OpRun)`) OR out-of-process
  via the `cmd/serve` shim — both run the same effect.
- **Release**: on a `v*` tag, publishes the prebuilt `generate-packages-linux-<arch>`
  binaries (amd64 + arm64) + the committed `generate-packages.providers` manifest
  as release assets, for the per-distro package repos to bake.
