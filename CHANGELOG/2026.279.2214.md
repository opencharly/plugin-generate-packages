# 2026.279.2214 — chore(deps): bump the sdk to v0.2026279.2204 — adopt the variant-family package relationships

## Summary

Adopt **opencharly/sdk#349** (`v0.2026279.2204`) — the fix that makes `packagekit` declare the variant family's `Provides`/`Conflicts`/`Replaces`.

Without this bump, the distro package repos (`charly-{arch,debian,fedora,…}`) that build from THIS plugin's released binary keep shipping **mutually-un-installable variants**: every variant unconditionally installs the same `/usr/bin/charly` + `/usr/lib/charly/plugins/*`, so swapping `charly` → `charly-minimal` aborts on the shared files (measured on the published `charly-arch` repo, 27 shared paths). This is the consumer leg of the producer→consumer cutover (B6) for opencharly/sdk#348.

**Change:**
- `github.com/opencharly/sdk` `v0.2026256.1220` → `v0.2026279.2204` (the adopted change).
- `github.com/opencharly/spec` `v0.2026254.503` → `v0.2026276.0` — required by the sdk bump (its `go.mod` requires spec `v0.2026276.0`); MVS moves it.
- `go-digest` / `image-spec` + `x/{crypto,net,sys,text}` indirect bumps — MVS from the sdk's own dependency graph (nFPM); no plugin code depends on them.
- `candy/generate-packages/e2e_test.go` — assert the emitted `.PKGINFO` carries `provides`/`conflict`/`replaces` for a named variant, so the consumer boundary is covered.

Refs opencharly/sdk#348 (fixed at the builder by sdk#349).
