## The mechanism is now proven in BOTH directions

#3 showed only the failing invocation, which cannot establish that Go never falls back to a
root tag. An external control settles it, re-derived here rather than taken on report:

```
$ go list -m github.com/hashicorp/consul/api@v1.32.0     # prefixed tag api/v1.32.0 exists
github.com/hashicorp/consul/api v1.32.0                  # resolves

$ git ls-remote --tags https://github.com/hashicorp/consul refs/tags/v1.9.9
8159a14bed92f774437618587fc8b38fe603ade1  refs/tags/v1.9.9   # the ROOT tag genuinely exists

$ go list -m github.com/hashicorp/consul/api@v1.9.9
go: invalid version: unknown revision api/v1.9.9            # still not consulted
```

The negative case is the decisive one: an existing root tag is still ignored for a
subdirectory module.

## Deprecated runner

`actions/setup-go@v5` and `actions/checkout@v5` run on Node 20, which GitHub annotates as
deprecated on every run — visible on the 2026-08-15 release run, so pre-existing drift rather
than anything #3 introduced. Both bumped to `@v7` (current latest) in `ci.yml` and
`release.yml`. `ci.yml` runs on push, so this branch's own CI run is the test of the bump;
`release.yml` shares the identical two steps and no other input.
