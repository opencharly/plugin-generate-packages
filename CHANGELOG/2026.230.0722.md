## The mechanism is now proven in BOTH directions

#3 showed only the failing invocation, which cannot establish that Go never falls back to a
root tag. An external control settles it, re-derived here rather than taken on report:

```
$ go list -m github.com/hashicorp/consul/api@v1.32.0     # prefixed tag api/v1.32.0 exists
github.com/hashicorp/consul/api v1.32.0                  # resolves

$ git ls-remote --tags https://github.com/hashicorp/consul refs/tags/v1.9.9
8159a14bed92f774437618587fc8b38fe603ade1  refs/tags/v1.9.9   # the ROOT tag genuinely exists

$ go list -m github.com/hashicorp/consul/api@v1.9.9
go: invalid version: unknown revision api/v1.9.9            # still not consulted
```

The negative case is the decisive one: an existing root tag is still ignored for a
subdirectory module.

## Deprecated runner

`actions/setup-go@v5` runs on Node 20, which GitHub annotates as deprecated on every run —
visible on the 2026-08-15 release run, so pre-existing drift rather than anything #3
introduced. Bumped to `@v7` (current latest) in `ci.yml` and `release.yml`.

`actions/checkout@v5` is bumped to `@v7` in the same edit, but **for currency only, not for
the deprecation**. An earlier draft of this entry and of commit `863b51e9` claimed checkout@v5
also ran on Node 20. **It does not** — its `action.yml` declares `using: node24`, and each
annotation names exactly one action, `actions/setup-go@v5`. The bump is harmless and the
version is current; the justification was appended to a true measurement without being
checked, which is precisely the defect class this PR exists to repair.

The bump is tested by this PR's `ci.yml` run — **`ci` event=`pull_request`, conclusion
`success`, zero annotations** (all five prior runs carry the deprecation annotation).

## The push trigger never fired for a working branch — fixed here, not routed

`ci.yml`'s trigger was `on: push: branches: ['*']`, and `*` does not match a `/`, so it never
fired for a `feat/…` branch — the same glob semantics this cutover relied on for the release
tag filter, applied in the other direction and missed. Measured: 3 push-event `ci` runs, all
on `main`; zero across the four `feat/*` branches pushed to this repo.

An earlier revision of this PR ROUTED that fix to "the next workflow touch in this repo". That
routing was vacuous — this PR *is* a workflow touch of that exact file, four lines above the
broken trigger — and it named a condition rather than a batch with an owner. Fixed here
instead: `'*'` → `'**'`. The fix is self-proving; a push-event `ci` run for this branch appears
in this PR's own run list.

**Correction to the commit message of `863b51e9`:** it also said `ci.yml` runs on push so the
branch push would test the bump. It did not, for the reason above. Neither claim can be amended
out of a pushed commit without a forbidden force-push, so both are corrected here.
