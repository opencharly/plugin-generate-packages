# 2026.230.0708

Document the **Go-module tag contract** for this repository. A consumer that
`require`s the plugin as a Go module — the superproject's
`candy/generate-packages/` re-export shim, the last open unit of the nFPM
packaging cutover — needs a tag this repo has never minted, and the form is not
the one the program's north-star predicted.

- **The required tag is subdirectory-prefixed**:
  `candy/generate-packages/v0.<YYYYDDD>.<HHMM>`. The module lives in a repository
  subdirectory, so Go resolves its versions from a tag named for that
  subdirectory, not from a tag at the repository root.

  Measured, against this repository, with a purged module cache:

  ```
  $ go list -m github.com/opencharly/plugin-generate-packages/candy/generate-packages@v0.2026227.1233
  go: ...@v0.2026227.1233: invalid version:
      unknown revision candy/generate-packages/v0.2026227.1233
  ```

  Go names the ref it looked for. A bare root `v0.2026227.1233` — the form the
  north-star document prescribed — would not have been consulted at all.

- **The stated blocker does not reproduce.** The north-star records the cause as
  semver rejecting the CalVer tag (leading-zero patch). That is true of the tag
  *form*, but it is not what blocks a consumer today: the module already resolves
  via pseudo-version.

  ```
  $ go list -m .../candy/generate-packages@latest
  github.com/.../candy/generate-packages v0.0.0-20260815123931-cf852b9ad3b6
  ```

  So the shim is **not blocked** on this tag. The tag supplies release identity,
  not resolvability — a smaller claim than the one on record, and the correction
  is being carried back to the north-star in the superproject leg.

- **The module tag publishes no duplicate release.** The release workflow's
  `on.push.tags` filter is `v*`, and a tag named `candy/generate-packages/v0.…`
  does not begin with `v`. This follows from the filter's glob semantics, not from
  an observed run — no non-`v` tag has ever existed in this repo, so there is no
  workflow run to cite. The first module tag is the observation; if the release job
  does fire, the fix is an explicit exclusion, and this entry is the record of the
  prediction. No workflow change is made now, because adding an exclusion for a
  problem that has not been shown to exist would be a workaround.

- **Both tags are minted at merge on the same merged HEAD**: `v<YYYY.DDD.HHMM>`
  (release, per repo convention) and `candy/generate-packages/v0.<YYYYDDD>.<HHMM>`
  (Go module). `<HHMM>` strips leading zeros, mirroring the sdk scheme.

No plugin code changes. Documentation only: `README.md` gains a
*Go-module consumption* section under `## Release`.
